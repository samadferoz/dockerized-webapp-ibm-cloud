Architecture

The Dockerfile, explained

# Stage 1: install dependencies
FROM node:20-alpine AS deps          # small Linux + Node
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm ci --omit=dev                # only production packages

# Stage 2: final small image
FROM node:20-alpine
COPY --from=deps ... node_modules    # take only what we need
COPY app.js server.js public ./
USER node                            # run as normal user, not root
EXPOSE 3000                          # app listens on 3000
HEALTHCHECK ... /health              # Docker checks app is alive
CMD ["node", "server.js"]            # start command

Quick concepts

What is Docker?

Docker packs an app with everything it needs (Node, libraries) into one container, so it runs the same on any machine.

Image vs container?

An image is the recipe. A container is the running dish made from that recipe.

Why a multi-stage build?

Stage 1 installs packages, stage 2 copies only what is needed. The final image is smaller and safer.

What does the health check do?

Every 30 seconds Docker calls /health. If the app does not answer, the container is marked unhealthy.

What is CI/CD here?

On every git push, GitHub Actions runs the tests, builds the image and pushes it to the registry automatically.

Container vs virtual machine?

A VM runs a full operating system (heavy). A container shares the host OS (light and fast).
